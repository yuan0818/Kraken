# 测试看板

入口：`#/overview`（导航名称“看板”）。默认最近 7 天、真机执行、全部任务；可切换 7 / 30 / 90 天、模拟 / 全部执行及具体任务。每 15 秒更新，也支持手动刷新。请求失败时保留上次成功的结果并显示错误；切换筛选后清空旧统计，避免混淆。

## 统计口径

- 数据来自控制面 PostgreSQL 的 runs、case_runs、attempts；不依赖节点数据库，也不使用执行列表的 100 条上限。
- 时间范围为 Asia/Taipei 本地日期，从起始日 00:00 到查询时刻，按批次创建时间筛选。趋势按批次创建日期归组，呈现目前最新结果，不代表当天结束的执行量。
- 同一批次的每条用例仅计一次，结论取编号最大的尝试。不同批次中的同一用例分别计数。尝试总数包含重试；首跑通过取最早尝试。
- 通过率 = 最新结论为通过的用例数 / 已有结论的用例数。分母包含通过、失败、阻塞、结论不充分，不包含尚未评估。没有分母时显示“—”。
- 启动前被阻塞的批次仍计入批次数；从冻结的用例列表计算未执行项，归为“尚未评估”，不当作断言失败。
- 批次状态复用执行记录的状态判定，包括等待重试、待恢复等；已结束不等于全部通过。
- 真机 / 模拟以冻结任务的目标设备配置区分；历史非任务批次以持久化的尝试 simulation 字段识别。
- ANR / Crash 统计所选批次所有尝试中上报的事件（包括重试），同时展示真机尝试的采集完成数与截断数。没有采集记录或未完成采集不能证明没有异常。
- 实时资源使用平台设备、节点状态，不受上方历史筛选影响，页面明确标识。

## 查看详情

需要关注的执行显示最近批次中的失败、阻塞、结论不充分、待恢复项及具体原因，最多 10 项。点击进入对应尝试的执行详情；启动前阻塞进入批次报告。最近批次显示 8 项，可直接打开报告；数量限制只影响明细展示，不影响汇总统计。

## 接口与验证

`GET /api/dashboard?days=7&mode=physical&task_id=<可选 UUID>`。
`days` 范围 1–90，`mode` 为 `physical`、`simulation` 或 `all`。查询使用 REPEATABLE READ，保证一次响应内部数据一致；返回统计和精简明细，不加载截图、报告大对象或模型密钥。

集成测试：`.venv/bin/pytest tests/integration/test_dashboard.py -q`。覆盖超过 100 个批次、重试去重、真机 / 模拟与任务筛选、预检阻塞、跨尝试稳定性事件、本地日期边界、空数据和参数校验。
