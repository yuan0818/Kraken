# 测试任务与执行批次

## 使用流程

1. 在“测试任务”点击“新建测试任务”，填写名称与说明。创建得到空的用例集合，不会占用设备或开始执行。
2. 进入任务，点击“添加用例”。弹窗默认检索全部已启用用例，支持编号、名称/关键词、模块、级别、测试目的、对象及 Android/App 版本筛选；分页加载，跨页和跨筛选保留选择，已在任务中的用例不可重复添加。
3. 添加后可移除、上移、下移。未设置 Stable 的已启用用例也可先加入；执行前必须为所有成员设置已启用的 Stable。选择和列表展示使用最新编写内容，实际执行使用开始授权时的 Stable，两者可能不同。
4. 配置并发/顺序执行、定时、刷机要求及重试，点击“保存任务”。未保存时不能立即执行；保存失败或版本冲突保留当前输入。
5. 点击“立即执行”，或等待定时触发。每次产生独立执行批次；在执行记录中查看逐用例状态、全部尝试、实际内容快照、断言结论、清理及证据完整性。

用例页的“建任务”是快捷入口：创建任务并加入当前用例，仍需到任务页保存配置和显式执行。任务名称与配置可重复编辑；每次保存产生不可变配置版本，修改仅影响后续触发的批次。已有批次的用例集合与规则保持不变。任务不会固定 Case Version；每次新 attempt 仍在节点 ready 的开始授权事务中读取当前 Stable。

## 执行规则

| 配置 | 当前行为 |
| --- | --- |
| 并发执行 | 最大并发用例数 1–60，仍受可用设备与匹配约束限制，每部设备独占 |
| 执行模型 | 从已启用模型中选择；触发批次时固定当前配置与 Key 版本，之后编辑或轮换不影响排队/运行/重试。停用阻止新批次。当前模拟任务可不选且不会调用模型 |
| 顺序执行 | 按任务列表顺序执行，前一用例的自动重试结束后才派发下一用例 |
| 定时执行 | 每天或每周，配置时刻和时区；每周可多选日期。关闭定时保留历史批次 |
| 同任务重叠 | 手动和定时批次统一按创建顺序排队，上一批次未结束或仍持有设备租约时不开始下一批 |
| 停机补跑 | 每个任务只补最近一次错过的计划时刻；已有队列保留。任务 ID + 计划时刻幂等 |
| 时区 | 后端支持 IANA 时区，页面提供 Asia/Taipei、Asia/Shanghai、UTC；夏令时缺失时刻跳过，重复时刻只取第一次 |
| 失败重试 | 0–10 次，不含首跑；间隔 0–86400 秒，从前次结束计算。失败、阻塞和证据不足可重试，达到上限或通过即停止 |
| 重试安全边界 | 前次必须已结束、清理确认、租约释放。取消、状态未知或清理失败不自动重试。每次保留原结果并创建新 attempt |
| 批次取消 | 取消队列和活动尝试，并停止后续自动重试；活动设备等待节点确认停止和清理后释放。已结束批次的取消请求不改写历史 |
| 刷机 | 可保存 Fastboot 全量刷机要求与内网包来源；真实适配器未接入，手动执行被拒绝，定时生成带原因的阻塞批次，绝不忽略刷机要求 |

刷机来源不要写账号密码；当前字段仅保存位置，尚不读取 SMB/FTP、解析最新包或调用 Fastboot。真实 Artemis、完整准备/刷机/清理任务链、环境矩阵、录像、Cron 与包身份解析仍属于后续交付。当前模拟执行正常结束为 `completed / inconclusive / verified / partial`，不表示手机断言通过。

## 数据与 API

升级前备份 PostgreSQL，执行 `alembic upgrade head` 应用 `0005_tasks`，重启 API 与调度器。原单用例历史保留，展示为“历史单用例执行”；新任务页与新批次详情使用以下接口：

- `GET/POST /api/tasks`：检索/创建任务；`scheduled=true` 只列启用定时的任务。
- `GET/PUT /api/tasks/{id}`：读取/保存；保存须携带 `expected_revision`，冲突返回 409。
- `POST /api/tasks/{id}/execute`：携带请求 UUID 与配置版本，重发同一请求只得到同一批次。
- `GET /api/executions?task_id=…`：最近 100 个批次；省略 task_id 返回全局历史。
- `GET /api/executions/{id}`：批次配置和全部用例尝试。
- `POST /api/executions/{id}/cancel`：整批取消。

自动定时审计归属 `scheduler` 系统主体。手动操作沿用当前访问主体；开放模式不冒充真实登录用户。旧单用例 `/api/runs` 端点保留兼容，不用于新任务页面。


## 执行期间的 ANR 与 Crash

真机节点从提交 Artemis 到本次尝试结束，持续采集指定 SN 的 ActivityManager 事件。批次详情按用例和尝试展示 ANR、Crash、进程、PID、换算后的发生时间及原始事件。时钟变化、采集连接中断和达到保留上限时会显示覆盖状态。采集结果单独保存，断言、重试和设备租约仍按测试本身的结果处理。每次尝试最多保留 100 条事件。完整 ANR trace、tombstone 和系统重启需另外取证。

高频 UI 稳定性场景可将一组固定动作封装成可重复脚本，通过 Artemis 执行用例调用。例如在测试 App 内按固定节奏重复进入页面、滚动并返回，明确轮数、动作间隔、目标包和清理步骤。将动作序号与时间写入脚本输出，便于拿执行日志与异常时间对照。常规用例和高频用例分开建任务，便于比较相同设备、构建和模型下的发现。批次报告中的事件表示在采集窗口观察到的现象，归因需要核对进程、异常原因和动作日志。
