# 效果检测工具

测试任务的执行配置增加“效果检测工具”：画面质量检测（FrameGuard）、声音质量检测（AudioGuard）。默认不启用；选择后按批次冻结，任务后续修改不影响已有批次。用例继续用自然语言描述操作与效果预期，执行引擎负责调用 Tool。

节点需升级执行引擎并配置常驻检测服务。部署说明见相邻执行引擎仓库 `../artemis/integrations/quality/README.md`（部署者可自行调整目录）。默认辅助诊断，尚未经过独立真实样本校准的权重不能直接作为质量门禁。现有大模型配置独立于这两个检测器。

引擎 `/api/run/defaults` 声明 `quality_tools_version=1` 和可用的检测工具；节点发现所选工具未配置时明确拒绝启动。服务已配置但运行中不可用、无音轨、录制缺口、覆盖不足，都记录为无法判定。

执行报告增加“画面与声音效果”区域：展示检查目的、独立效果结论、关联步骤、采样范围、原始图片或可播放录屏，点击异常时间可定位。缺失媒体明确标记。结果由控制面数据库保存；节点仅暂存传输材料，沿用原有报告重试上传机制。模型异常与 ANR/Crash 是不同证据来源，不能互相替代。

数据库迁移：`.venv/bin/alembic upgrade head`，新增 `0016_quality_media`。当前媒体沿用控制面存储方式，每个文件最多 32 MiB，按 attempt_id + SHA-256 去重；删除执行尝试时级联删除媒体。大规模长期录音录像建议后续迁移对象存储；本次没有新增自动过期清理任务。

兼容旧引擎（未选择效果检测时）；旧报告没有 quality 字段仍正常显示。新旧节点混部前应先升级节点协议包，再启用工具。控制面只投影专用质量结果，不拷贝通用工具调用中的原始提示或模型思考。

验证：任务/命令配置传递、已有报告增强、历史报告保护、媒体校验、节点/执行尝试隔离、证据上传及重试。真实权重使用合成黑屏/单音片段跑通；未宣称真实设备音画质量准确率。
