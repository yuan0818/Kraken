# 用例导入与版本并发规则

更新：2026-10-22。当前交付 Excel 文本 `.xlsx` 入口；飞书普通电子表格的手动和定时读取均已确认，连接器与调度尚待开发。定时读取也必须生成预览，经用户采纳后才形成平台版本。

## 操作流程

1. 在基础数据中维护系统模块、App、App 模块、App 版本、Android 版本、机型、芯片平台。App 模块和版本必须归属相应 App。
2. 在导入中心上传 `.xlsx`，选择工作表和表头行，填写固定来源名称。映射编号、模块、测试目的、步骤、预期结果五个必填字段，其余按需映射。
3. 查看预览，展开行查看字段差异与来源原文；校验失败的行不可选择。相同编号来自未关联来源时，必须确认关联；平台和来源都改过时，必须确认采纳来源修改。
4. 选择要处理的行，点击采纳。所有选中行在同一事务提交；任何行的版本、来源基线或基础数据在预览后改变，则整批拒绝，重新预览后再处理。
5. 结果提供用例版本链接。需要用于测试时，进入用例详情单独设置 Stable。批次完成后不可改变原选择；未选行可通过新预览继续处理。

## 文件格式

每行一个用例，编号使用文本格式，大小写不区分。编号仅允许字母、数字、下划线、点和连字符，最长 80 字符；禁止用行号或标题推测身份。未映射名称时，新用例以测试目的前 200 字为名称，已有用例保留名称；映射名称与同编号已有名称不符时提示核对。

| 字段 | 内容 |
| --- | --- |
| 被测对象 | `android_os` / `Android OS` / `OS` 或 `app` / `App`；未映射时使用页面默认对象 |
| 模块、App、版本、机型、芯片 | 与已启用基础数据名称匹配；App 模块和 App 版本按所属 App 限定 |
| 前置条件、步骤、预期结果 | 单元格内换行分条，保留非空条目的次序与文本 |
| Android/App 版本、机型、芯片、设备标签 | 多个值用换行或中英文分号分隔；不把普通逗号当分隔符 |
| 级别 | `P0` / `P1` / `P2` / `P3`，新用例默认 `P2` |
| 状态 | 草稿 / 启用 / 停用，或 `draft` / `active` / `disabled`，新用例默认启用 |

App 用例关联自身版本，不接受 Android 版本和芯片平台。OS 用例不接受 App 关联。

未映射的可选字段保留已有版本值；已映射的空值会清空相应字段，必填字段为空仍报错。原文件完整保留，但未映射列不成为执行内容。当前限制为文件 10 MB、解压总量 40 MB、最多 20 个工作表/50 列，单表最多 2000 条数据与前 20 行表头；一批处理一个工作表。公式和 Excel 错误值定位到行，合并单元格、图片、嵌入附件、宏拒绝解析，避免无提示遗漏测试要求。旧 `.xls` 应先转为 `.xlsx`。这些规则仍需使用用户实际样例完成 Q06 验收。

## 来源与幂等

来源身份为 `excel + 固定来源名称 + 工作表名 + 不区分大小写的编号`。后续文件名可以变化，但固定来源和工作表名保持一致；插行和排序不会产生重复 Case。相同来源内容未变时保留平台当前版本，即使平台已编辑或历史基础数据已停用，也不回退平台内容。

来源变更、平台未变时追加版本；双方都变时明确确认后追加版本。来源与平台内容一致则仅更新关联基线，不新增版本。不同来源同编号必须逐行确认关联，不按名称自动合并。来源缺行不删除平台用例，不移动 Stable，不向外部回写。Excel 的预览/原文件/结果保留在数据库，NAS 归档与清理策略仍随存储任务实现。

预览请求携带 UUID，原请求重试返回同批次，改变映射必须使用新 UUID。已采纳批次以同一选择重试返回原结果，不同选择返回冲突。接受操作锁定批次、来源及用例后检查基线；异常时所有所选行回滚。

## API 与迁移

| API | 用途 |
| --- | --- |
| `POST /api/imports/excel?filename=...` | 原始二进制请求体上传；非 multipart |
| `GET /api/imports/uploads/{id}` | 工作表与前 20 行样本 |
| `GET /api/imports/uploads/{id}/file` | 下载上传的原文件 |
| `POST /api/imports/preview` | 文件 ID、来源、工作表、表头行、字段到零基列索引映射、默认对象、请求 ID |
| `GET /api/imports` / `GET /api/imports/{id}` | 最近 100 批次 / 完整预览与结果 |
| `POST /api/imports/{id}/accept` | 原始行号数组 `rows` 与逐行确认的 `acknowledged_conflicts` |

Stable 写入 API 现在必须包含 `expected_version_id`，首次设置传 `null`；观察值过期返回 409，不会覆盖他人切换。用例编辑页面向版本创建 API 传 `expected_latest`（无版本为 `none`），发生并发修改返回 409，表单内容保留。历史版本仍可作为新版本来源，但检查的是打开编辑时最新编写版本。旧的可信 API 调用不传 `expected_latest` 时仍允许追加版本。

数据库迁移 `0004_imports` 增加上传、批次和来源关联表，并使版本时间记录锁定用例后的实际插入时刻。应用升级前备份，停止旧服务，执行 `alembic upgrade head` 后重启。已有 Case、版本、Stable 和执行快照保留；不支持直接降级删除来源记录，应按备份恢复方案处理。API 类型由 contracts 导出生成。
